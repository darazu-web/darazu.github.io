## 0-1. 環境を2つ用意する

Power Platform 管理センター > 環境 > 新規

| | 開発 | 本番 |
|---|---|---|
| 名前 | `設備管理-開発` | `設備管理` |
| 種類 | サンドボックス | 運用 |
| Dataverse | あり | あり |
| 言語 | 日本語 | 日本語 |
| 通貨 | JPY | JPY |

**本番で直接作らないでください。** 一度本番に手で作ったテーブルは、
後からソリューションで管理し直すのが非常に面倒になります。

> 言語は後から追加できますが、**基本言語は変更できません**。
> 日本語を基本言語にしておかないと、テーブルの表示名が英語で作られます。
> `Deploy-Schema.ps1` は環境で日本語が有効かを確認し、無効なら警告を出して止まらずに進みます。

## 0-2. Entra セキュリティグループを作る

Microsoft Entra 管理センター > グループ > 新しいグループ

| グループ名 | 種類 | 用途 |
|---|---|---|
| `設備-使用者` | セキュリティ | 現場の使用者全員 |
| `設備-管理者` | セキュリティ | 設備管理の担当者 |

作成したら**オブジェクト ID を控えてください**。`Deploy-Security.ps1` に渡します。

```powershell
.\Deploy-Security.ps1 -EnvironmentUrl 'https://contoso-dev.crm7.dynamics.com' `
    -UserGroupObjectId  '<設備-使用者のオブジェクトID>' `
    -AdminGroupObjectId '<設備-管理者のオブジェクトID>'
```

グループ経由で権限を配ると、入社・異動のたびに Power Platform を触らずに済みます。
**人単位でロールを割り当てないでください。** 必ず破綻します。

## 0-3 / 0-4. ソリューションと公開元

このリポジトリのスクリプトが自動で作ります。手で作る必要はありません。

| 項目 | 値 | 変更 |
|---|---|---|
| 公開元 表示名 | 設備管理 | 後から可 |
| 公開元 一意の名前 | `eqmpublisher` | 不可 |
| **接頭辞** | **`eqm`** | **不可** |
| 選択肢の値の接頭辞 | `63400` | 不可 |
| ソリューション名 | 設備管理 (`EquipmentManagement`) | 表示名のみ可 |

**接頭辞は後から変更できません。** 変えたい場合は、最初の `Deploy-Schema.ps1` を実行する前に
`schema/dataverse-schema.json` の `eqm` をすべて置換してください。実行後に気づいた場合、
テーブルを作り直す以外に方法はありません。

`eqm` 以外にする場合の手順：

```powershell
# 例: 接頭辞を eqp にする
(Get-Content .\schema\dataverse-schema.json -Raw -Encoding UTF8) `
    -replace 'eqm_', 'eqp_' -replace '"eqm"', '"eqp"' -replace 'eqmpublisher', 'eqppublisher' |
    Set-Content .\schema\dataverse-schema.json -Encoding UTF8

(Get-Content .\schema\security.json -Raw -Encoding UTF8) -replace 'eqm_', 'eqp_' |
    Set-Content .\schema\security.json -Encoding UTF8

.\scripts\Test-Solution.ps1   # 置換漏れがないか確認する
```

**0-3 を飛ばして既定のソリューションに作ると、本番移送ができません。**
スクリプトは必ずソリューションを作ってからテーブルを作ります。

## 0-5. サービスアカウントを用意する

フローの所有者にする専用アカウントです。

| 項目 | 内容 |
|---|---|
| 表示名 | 設備管理システム |
| UPN 例 | `svc-equipment@contoso.com` |
| ライセンス | Power Automate Premium（または対象環境で動く同等のもの）、Exchange Online（メール送信用） |
| 多要素認証 | 対話ログインが不要な構成にする（条件付きアクセスの除外、またはアプリ登録を使う） |
| Dataverse ロール | 設備-システム（`Deploy-Security.ps1` が作成） |

**フローを個人アカウントで作らないでください。** その人が異動・退職した時点で全フローが止まります。
これは「いつか直す」で済む問題ではなく、止まったことに誰も気づかないまま延滞通知が消える事故になります。
