## 4-3 ステータス列の読み取り専用化

タブ2の該当列を選び、プロパティで「**読み取り専用**」にチェックします。

> **これはセキュリティ境界ではありません。**
> 使用者ロールには設備の Write 権限があるため、API を直接叩けば書けます。
> フォームの読み取り専用は「うっかり触ってしまう」のを防ぐものです。
> 本当に止めたい場合は `phase1-data.md` の「使用者に設備の Write を与えることについて」を読んでください。

ステータスを手で直す必要がある場面は必ず起きます（4-9 のコマンドで対応します）。

## 4-4 ラベル未貼付一覧ビュー（必須）

設備 > ビュー > 新規　名前：**ラベル未貼付一覧**

| 項目 | 設定 |
|---|---|
| 絞り込み | `ラベル貼付状況` **が次の値と等しい** `未貼付` **または** `要再貼付` |
| | **かつ** `ステータス` **が次の値と等しくない** `廃棄` |
| 列 | 短縮番号 / 設備名 / 場所 / 種別 / ラベル貼付状況 / 管理部署 |
| 並べ替え | 場所 昇順 → 短縮番号 昇順 |

**場所順に並べる**のが要点です。貼付作業は場所を回りながらやるので、
番号順では現場が何度も往復することになります。

### 使い方

1. このビューを場所で絞り込んで印刷、または Excel にエクスポート
2. その場所を回ってラベルを貼る
3. 戻ってきたら、ビューで対象行を選択 → **一括編集**で `ラベル貼付状況` を `貼付済`、`ラベル貼付日` を当日に
4. 件数が減っていくのを毎日見る

進捗が見えないと貼付作業は必ず止まります。**残り件数が唯一の進捗指標です。**

## 4-5 その他のビュー

### 設備

| ビュー名 | 絞り込み | 並べ替え |
|---|---|---|
| 使用中の設備 | ステータス = 使用中 | 現在の使用開始日時 昇順 |
| **長時間稼働中の設備** | ステータス = 使用中 **かつ** 現在の使用開始日時 が **過去 24 時間より前** | 現在の使用開始日時 昇順 |
| メンテ期限切れ | 次回メンテ予定日 が **今日より前** かつ ステータス ≠ 廃棄 | 次回メンテ予定日 昇順 |
| メンテ期限が未設定 | 次回メンテ予定日 に **データが含まれない** かつ ステータス ≠ 廃棄 | 場所 昇順 |
| 故障・メンテ中 | ステータス = 故障 または メンテ中 | 場所 昇順 |

「過去 24 時間より前」は、日時列の絞り込み条件で **「次の時間より古い」→「時間」→ 24** を選びます。
相対条件なので、ビューを開くたびに現在時刻を基準に再計算されます。

### 稼働ログ

| ビュー名 | 絞り込み |
|---|---|
| 本日のログ | 開始日時 が **今日** |
| 稼働中のログ | 状態 = 稼働中 |
| 強制終了されたログ | 状態 = 強制終了 |
| 今月のログ | 開始日時 が **今月** |

### 使用者

| ビュー名 | 絞り込み | 用途 |
|---|---|---|
| 有効な使用者 | 有効 = はい | 既定 |
| UPN 未設定の使用者 | UPN に データが含まれない | **アプリに入れない人の一覧**。ここが空でないと問い合わせが来る |

## 4-7 ダッシュボード

名前：`設備管理ダッシュボード`

| 配置 | 種類 | 内容 |
|---|---|---|
| 左上 | 円グラフ | 設備の**ステータス別件数**（設備 / ステータスで group by） |
| 右上 | 横棒グラフ | **場所別の使用中台数**（設備、ステータス=使用中、場所で group by） |
| 左下 | 一覧 | ビュー「長時間稼働中の設備」 |
| 右下 | 一覧 | ビュー「延滞」 |

**ラベル貼付の進捗**は展開期間中だけ必要なので、別ダッシュボード
`展開進捗` に「ラベル貼付状況別の件数」の円グラフを1つ置くのが実用的です。
展開が終わったらサイトマップから外してください。

## 4-8 〜 4-10 カスタムコマンド

モデル駆動アプリのコマンドバーで「コマンドの編集」→ 新しいコマンド → 操作の種類：**Power Fx**

コマンドから Dataverse を書くには、コマンドの数式バー右上の「データ」で
`設備` と `稼働ログ` をデータソースに追加してください。

### 4-8 強制終了（設備のグリッド／フォーム）

終了し忘れた稼働ログを管理者が閉じます。

**表示**（Visible）
```
Self.Selected.Item.ステータス = 'ステータス (設備)'.使用中
```

**選択時**（OnSelect）
```
If(
    Confirm(
        "この設備の使用を強制終了します。" & Char(10) &
        "実際の終了時刻が分かっている場合は、先に稼働ログの終了日時を直してください。",
        { Title: "強制終了", ConfirmButton: "強制終了する", CancelButton: "やめる" }
    ),

    With(
        { 対象設備: Self.Selected.Item },
        With(
            {
                対象ログ: First(
                    Sort(
                        Filter('稼働ログ', 設備 = 対象設備, 状態 = '状態 (稼働ログ)'.稼働中),
                        開始日時,
                        SortOrder.Descending
                    )
                )
            },
            If(
                !IsBlank(対象ログ),
                Patch(
                    '稼働ログ',
                    対象ログ,
                    {
                        終了日時: Now(),
                        稼働時間: RoundDown(DateDiff(対象ログ.開始日時, Now(), TimeUnit.Minutes), 0),
                        状態: '状態 (稼働ログ)'.強制終了,
                        強制終了理由: "管理者による強制終了",
                        強制終了者: LookUp('使用者', Lower(UPN) = Lower(User().Email))
                    }
                )
            );

            Patch(
                '設備',
                対象設備,
                {
                    ステータス: 'ステータス (設備)'.空き,
                    現在の使用者: Blank(),
                    現在の稼働ログ: Blank(),
                    現在の使用開始日時: Blank()
                }
            );

            Notify("強制終了しました。", NotificationType.Success)
        )
    )
)
```

ログが見つからない場合でも設備側は「空き」に戻します。
設備が使えないまま残るほうが、現場にとっては大きな損害だからです。

### 4-9 状態の手動修正（設備のフォーム）

整合性チェックで拾えない例外に対応するための逃げ道です。**これは必ず必要になります。**

**表示**：常に表示（管理者アプリからしか開けないため）

**選択時**
```
If(
    Confirm(
        "設備の状態を「空き」に戻します。稼働ログや貸出には手を加えません。" & Char(10) &
        "使用中・貸出中の実体が残っている場合は、先にそちらを処理してください。",
        { Title: "状態の手動修正", ConfirmButton: "空きに戻す", CancelButton: "やめる" }
    ),
    Patch(
        '設備',
        Self.Selected.Item,
        {
            ステータス: 'ステータス (設備)'.空き,
            現在の使用者: Blank(),
            現在の稼働ログ: Blank(),
            現在の使用開始日時: Blank(),
            備考: Trim(
                Coalesce(Self.Selected.Item.備考, "") & Char(10) &
                Text(Now(), "yyyy/mm/dd hh:mm") & " " &
                User().FullName & " が状態を手動修正しました"
            )
        }
    );
    Notify("状態を「空き」に戻しました。", NotificationType.Success)
)
```

**備考への追記を省略しないでください。** 誰がいつ手で直したかが残らないと、
同じ不整合が繰り返し起きているのか、一度きりなのかが分からなくなります。

### 4-10 メンテ完了（設備のグリッド／フォーム）

**表示**
```
Self.Selected.Item.ステータス = 'ステータス (設備)'.メンテ中
```

**選択時**
```
With(
    {
        対象: Self.Selected.Item,
        周期: Coalesce(
            Self.Selected.Item.メンテ周期日数,
            Self.Selected.Item.種別.既定メンテ周期日数,
            0
        )
    },
    Patch(
        '設備',
        対象,
        {
            ステータス: 'ステータス (設備)'.空き,
            前回メンテ日: Today(),
            次回メンテ予定日: If(周期 > 0, DateAdd(Today(), 周期, TimeUnit.Days), Blank())
        }
    );
    Notify(
        "メンテ完了を記録しました。次回予定日: " &
        Coalesce(Text(DateAdd(Today(), 周期, TimeUnit.Days), "yyyy/mm/dd"), "未設定"),
        NotificationType.Success
    )
)
```

周期が未設定の設備は次回予定日が空のままになります。
それを拾うのがビュー「メンテ期限が未設定」（4-5）です。
