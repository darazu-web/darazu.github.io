## 毎日やること（5分）

### 1. 朝のメールを見る

| 件名 | 意味 | 対応 |
|---|---|---|
| 【設備】整合性チェック | データのずれ | 「人の確認が要る分」だけ対応する |
| 【設備】24時間以上 稼働中のまま | 終了忘れの疑い | 使用者に確認 → 必要なら強制終了 |
| 【設備】延滞 ○件 | 返却期限超過 | 持出者に連絡 |
| 【設備】メンテ期限 ○件 | メンテ予定 | 日程を調整 |
| **【設備】フロー失敗** | **フローが止まった** | **最優先で対応**（下記） |

**メールが1通も来ない日が続いたら、それは正常ではなくフローが止まっている可能性です。**
週に1回、Power Automate の実行履歴を目視してください。

### 2. 終了忘れの処理

1. 管理者アプリ > 設備 > ビュー「長時間稼働中の設備」を開く
2. 使用者に確認する（実際にまだ使っているなら何もしない）
3. 使い終わっていれば：
   - 実際の終了時刻が分かる → 稼働ログの `終了日時` を手で直してから **強制終了**
   - 分からない → そのまま **強制終了**（終了日時は現在時刻になる）

**先に終了日時を直す**のを忘れないでください。後から直すと稼働時間が再計算されません。

## 毎週やること（15分）

- [ ] Power Automate > 自分のフロー で、5本すべての実行履歴を見る（成功しているか）
- [ ] ビュー「UPN 未設定の使用者」が 0 件か
- [ ] ビュー「メンテ期限が未設定」の件数が増えていないか
- [ ] 稼働ログの件数が前週から大きく減っていないか（減っていたら使われなくなっている兆候）

## 毎月やること（30分）

### 1. 人の異動を反映する

```powershell
# Entra から最新の名簿を取る
Connect-MgGraph -Scopes 'User.Read.All'
Get-MgUser -All -Property Id,UserPrincipalName,DisplayName,EmployeeId |
    Select-Object @{n='社員番号';e={$_.EmployeeId}},
                  @{n='氏名';e={$_.DisplayName}},
                  @{n='UPN';e={$_.UserPrincipalName.ToLower()}},
                  @{n='EntraオブジェクトID';e={$_.Id}} |
    Export-Csv .\entra-users.csv -NoTypeInformation -Encoding utf8BOM
```

`部署` `既定の場所` `役割` を埋めてから投入します。

```powershell
.\Import-MasterData.ps1 -EnvironmentUrl '<本番URL>' -Table 使用者 -CsvPath .\entra-users.csv
```

退職者は行を消すのではなく、`有効` を `無効` にしてください。
過去の稼働ログから名前が消えると、履歴が追えなくなります。

### 2. 設備の増減を反映する

新規設備：

```powershell
# 1. eqm_equipments.csv に行を足す（短縮番号は空欄でよい）
# 2. 既存の番号と衝突しないよう、本番の番号を書き出して渡す
.\New-ShortNumber.ps1 -ExistingNumbersCsv .\live-numbers.csv
# 3. 出力を確認して投入
.\Import-MasterData.ps1 -EnvironmentUrl '<本番URL>' -Table 設備
# 4. ラベルを印刷して貼る
```

廃棄設備：管理者アプリで `ステータス` を〔手動修正コマンド経由で〕`廃棄` にします。
**行は消さないでください。** 過去の稼働ログが孤児になります。

### 3. フローの目視確認

Power Automate > 自分のフロー > 各フロー > 実行履歴 を開き、
直近1か月に**失敗が1件もない**ことを確認します。

自動監視（5-4）は「気づくまでの時間」を短くするものであって、ゼロにはできません。
月1回の目視が最後の網です。

## 年に1回やること

- [ ] サービスアカウントのパスワード・ライセンスの有効期限

## 困ったときの対応

### フローが失敗した

1. 失敗通知メールの「エラーの内容」を読む
2. Power Automate で該当の実行を開き、赤いアクションを見る

| よくある原因 | 対応 |
|---|---|
| 接続の認証切れ | Power Automate > 接続 で該当の接続を修復 |
| サービスアカウントのライセンス失効 | ライセンスを再割り当て |
| 権限不足 | 「設備-システム」ロールが付いているか確認 |
| 宛先メールアドレスが空 | 管理者グループの設定を確認 |

直したら**手動で1回実行**して、成功することを確認してください。

### 現場から「アプリが使えない」と言われた

| 症状 | 確認すること |
|---|---|
| サインインしても「ご利用いただけません」 | 使用者マスタに UPN があるか、`有効` になっているか |
| 番号を入れても見つからない | 短縮番号が正しいか、`廃棄` になっていないか |
| ボタンが出ない | 他人が使用中の設備を開いていないか（仕様） |
| 保存できない | 電波状況。画面上端に赤帯が出ていないか |
| 一覧に設備が出てこない | 場所が正しいか。委任の上限（2000件）に達していないか |

詳細は `troubleshooting.md` を参照してください。

### 設備の状態がおかしい

管理者アプリのカスタムコマンド「状態の手動修正」（4-9）で「空き」に戻せます。
**備考に自動で記録が残ります。** 同じ設備で繰り返し起きているなら、
通信環境か操作手順に原因があります。

## 変更を加えるとき

**本番で直接テーブルや数式を触らないでください。**

```
開発環境で変更 → 動作確認 → ソリューションのバージョンを上げる
→ マネージドでエクスポート → 本番にインポート → 動作確認
```

スキーマ（列・テーブル）を変えた場合は、必ず先に検査を流してください。

```powershell
.\Test-Solution.ps1
```

数式・CSV・セキュリティ定義のどこかが追随していなければ、ここで見つかります。
