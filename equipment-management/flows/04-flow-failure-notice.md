# 5-4 フローの失敗時通知

**このフェーズで最も省略されやすく、最も省略してはいけない項目です。**

フローが止まっていることに誰も気づかないまま数週間が過ぎる、というのがこの手の仕組みで
いちばん多い事故です。延滞通知が来ないのは「延滞がないから」ではなく「フローが死んでいるから」
かもしれません。**通知が来ないことは、正常の証拠になりません。**

対策は2段構えにします。

- **A. 各フローに内蔵する**（必須・5分でできる）… そのフローが落ちたら即通知
- **B. 監視フロー**（推奨）… A の通知自体が送れなかった場合の保険

## A. 各フローに内蔵する（5-1, 5-2, 5-3, 5-5 すべてに入れる）

### 手順

1. フローの**既存アクションをすべて選択**し、**スコープ**の中へ入れる。名前を `試行` にする。
2. `試行` の下に新しい**スコープ**を追加し、名前を `エラー処理` にする。
3. `エラー処理` の「…」→ **実行条件の構成** で、次の3つにチェックを入れる。
   - に失敗しました
   - はスキップされました
   - がタイムアウトになりました

   （**「に成功しました」のチェックは外す**。外し忘れると毎回通知が飛びます）
4. `エラー処理` の中に **メールを送信する (V2)** を置く。

### 通知メールの中身

| 項目 | 値 |
|---|---|
| 宛先 | 管理者グループ |
| 件名 | `【設備】フロー失敗: @{workflow()?['tags']?['flowDisplayName']}` |
| 重要度 | 高 |

本文：

```
フローが失敗しました。

  フロー名 : @{workflow()?['tags']?['flowDisplayName']}
  環境     : @{workflow()?['tags']?['environmentName']}
  実行 ID  : @{workflow()?['run']?['name']}
  発生時刻 : @{convertTimeZone(utcNow(),'UTC','Tokyo Standard Time','yyyy/MM/dd HH:mm')}

--- エラーの内容 ---
@{result('試行')}
```

`result('試行')` は、スコープ `試行` の中で失敗したアクションの入出力をすべて返します。
このひと手間で、Power Automate の画面を開かなくても原因の見当がつきます。

> `result()` に渡すのは**スコープの名前**です。スコープ名を変えたら式も直してください。
> 名前に日本語やスペースを使った場合、式の中では表示名をそのまま書きます。

## B. 監視フロー（`設備-フロー失敗通知`）

A が動かない場合（コネクタの認証切れなど、通知自体が送れない状況）の保険です。
**Power Automate Management** コネクタを使います。

### トリガー

**繰り返し** / 1日 / (UTC+09:00) 大阪、札幌、東京 / 9:00

### 手順1：対象フローの実行履歴を取る

**Power Automate Management > フロー実行を一覧表示する (List Flow Runs)**

| 項目 | 値 |
|---|---|
| 環境 | 対象の環境 |
| フロー | 5-1〜5-3, 5-5 の各フロー（フローごとにアクションを置く） |

### 手順2：直近24時間に成功した実行があるか調べる

**データ操作 > 選択** → **配列のフィルター処理** で次の条件に合う実行を抜き出します。

```
@and(
  equals(item()?['properties']?['status'], 'Succeeded'),
  greater(item()?['properties']?['startTime'], addHours(utcNow(), -24))
)
```

### 手順3：0件なら通知

**条件**: `length(body('フィルター処理'))` が **0 に等しい**

| 項目 | 値 |
|---|---|
| 件名 | `【設備】24時間以内に成功していないフローがあります` |
| 重要度 | 高 |

本文にフロー名と最後の実行結果を入れます。

### 監視フロー自身が止まったら？

B にも A のスコープ構成を入れます。それでも B 自体が動かなくなる可能性は残るので、
**月に1回、管理者が Power Automate の画面で実行履歴を目視する**運用を手順書に入れてください
（`docs/operations-manual.md` の月次作業）。

自動監視は「気づくまでの時間」を短くするものであって、ゼロにはできません。
月1回の目視は、その前提を運用で埋めるための最後の網です。
