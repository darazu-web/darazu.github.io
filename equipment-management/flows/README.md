フロー5本の設計です。Power Automate で作るときの「貼り付ける値」まで書いてあります。

| # | フロー名 | 起動 | 通知先 |
|---|---|---|---|
| 5-1 | `設備-返却期限・延滞通知` | 毎日 8:00 | 持出者＋管理者 |
| 5-2 | `設備-メンテ期限通知` | 毎日 8:05 | 管理者 |
| 5-3 | `設備-整合性チェック` | 毎日 7:50 | 管理者 |

## 作る前に決めること

### 所有者はサービスアカウントにする（フェーズ0-5）
フローは**必ずサービスアカウントで作成**してください。個人アカウントで作ると、その人が退職・異動した時点で全フローが止まります。
サービスアカウントには「設備-システム」ロールを割り当てます（`Deploy-Security.ps1` で作成済み）。

### 管理者の宛先
管理者への通知先は Entra セキュリティグループ「設備-管理者」のメールアドレスを使います。
グループにメールアドレスがない場合は、フロー内で使用者マスタから引きます。

```
役割 = 管理者 かつ 有効 = true の使用者の UPN をセミコロン区切りで連結
```

Dataverse「行を一覧」→ `eqm_users`、フィルター `eqm_role eq 2 and eqm_isactive eq true`、
その後「作成」アクションで式:

```
join(body('管理者を一覧')?['value'], ';')
```
※ `join` は文字列の配列にしか使えないので、先に「選択」アクションで `eqm_upn` だけの配列にしてから join します。

### タイムゾーン
「繰り返し」トリガーのタイムゾーンは **(UTC+09:00) 大阪、札幌、東京** を選びます。
一方、フィルター式の中で `utcNow()` を使う箇所は **UTC のまま**比較します。
Dataverse の日時列（UserLocal）は内部的に UTC で保持されているため、UTC 同士で比べるのが正解です。

日付のみの列（返却予定日・次回メンテ予定日）は時差の影響を受けるので、
`convertTimeZone(utcNow(),'UTC','Tokyo Standard Time','yyyy-MM-dd')` で日本時間の日付を作ってから比較します。

## 5-4 を省略しないこと

**フローが止まっていることに気づかないのが、この手の仕組みでいちばん多い事故です。**
5-1〜5-3, 5-5 の4本すべてに、`04-flow-failure-notice.md` の「スコープ＋実行条件の構成」を入れてください。
これはフローを1本作るたびに5分で終わる作業です。後からまとめてやろうとすると必ず漏れます。
