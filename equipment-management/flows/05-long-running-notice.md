# 5-5 長時間稼働通知（24時間・管理者のみ）

`設備-長時間稼働通知`

24時間を超えて「稼働中」のままの稼働ログを、管理者にだけ知らせます。

## 設計方針：最小構成にする

- **本人への段階的リマインドは作りません**（2時間後→4時間後…といった仕組みは不要）
- **通知済みフラグも使いません**

終了忘れは元々そう多くありません。凝った仕組みを作っても、動作確認と保守の手間が
効果を上回ります。まずは「毎朝、管理者が一覧で見る」だけにして、実際にどれくらい
発生するかをパイロット（フェーズ6-5）で測ってから判断してください。

> 稼働ログには `長時間通知済み` 列を用意してありますが、**この構成では使いません**。
> 毎日の再通知が煩わしくなったときに使える受け皿として置いてあるだけです。

## トリガー

**繰り返し** / 1日 / (UTC+09:00) 大阪、札幌、東京 / 8:10

## 手順1：24時間を超えた稼働中ログを拾う

**Dataverse > 行を一覧する**

| 項目 | 値 |
|---|---|
| テーブル名 | 稼働ログ (`eqm_operationlogs`) |
| 選択列 | `eqm_name,eqm_starttime,eqm_state` |
| フィルター行 | `statecode eq 0 and eqm_state eq 1 and eqm_starttime lt @{formatDateTime(addHours(utcNow(),-24),'yyyy-MM-ddTHH:mm:ssZ')}` |
| 展開クエリ | `eqm_EquipmentId($select=eqm_shortnumber,eqm_name),eqm_UserId($select=eqm_name,eqm_upn),eqm_LocationId($select=eqm_name)` |
| 並べ替え | `eqm_starttime asc` |

`eqm_starttime` は UserLocal 動作の日時列で、内部は UTC で保持されています。
そのため `utcNow()` との比較でそのまま正しく動きます。**日本時間に変換してから比べないでください**（二重に時差が乗ります）。

## 手順2：一覧を作る

**データ操作 > 選択**

```
{
  "番号": @{item()?['eqm_EquipmentId']?['eqm_shortnumber']},
  "設備名": @{item()?['eqm_EquipmentId']?['eqm_name']},
  "場所": @{item()?['eqm_LocationId']?['eqm_name']},
  "使用者": @{item()?['eqm_UserId']?['eqm_name']},
  "開始日時": @{convertTimeZone(item()?['eqm_starttime'],'UTC','Tokyo Standard Time','yyyy/MM/dd HH:mm')},
  "経過時間": @{div(div(sub(ticks(utcNow()),ticks(item()?['eqm_starttime'])),10000000),3600)}
}
```

最後の式は経過**時間**（整数）です。`ticks` の差はナノ秒の100分の1単位なので、
`10000000` で秒に、さらに `3600` で時間になります。

**データ操作 > HTML テーブルの作成** に渡します。

## 手順3：管理者へ送る

**条件**: `length(body('長時間稼働ログを一覧')?['value'])` が 0 **より大きい**

| 項目 | 値 |
|---|---|
| 宛先 | 管理者グループ |
| 件名 | `【設備】24時間以上 稼働中のまま @{length(body('長時間稼働ログを一覧')?['value'])} 件` |
| 本文 | HTML テーブル＋下の一文 |

```
終了忘れの可能性があります。使用者に確認のうえ、必要なら管理者アプリの
「強制終了」コマンドで終了させてください（実際の終了時刻が分かる場合は、
先に稼働ログの終了日時を手で直してから強制終了してください）。
```

**0件のときは送らない**でください。

## パイロットで見るところ（フェーズ6-5）

4週間の試行運用のあいだ、このメールの件数を数えておきます。

| 結果 | 次にやること |
|---|---|
| ほぼ0件 | このままでよい。閾値も変えない |
| 週に数件 | 24時間という閾値が業務実態に合っているか確認する（2日にまたがる作業が普通なら閾値を伸ばす） |
| 毎日大量 | 終了操作が定着していない。通知を増やすのではなく、**操作説明（6-3）と画面（3-4）を見直す** |

通知を増やして解決しようとすると、読まれない通知が増えるだけです。
