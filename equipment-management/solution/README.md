# 管理者アプリ（モデル駆動）のソリューション

フェーズ4のフォーム・ビュー・サイトマップ・アプリを、取り込める zip として組み立てます。
メーカーポータルで画面を1つずつ作る作業がなくなります。

| ファイル | 役割 |
|---|---|
| `app-definition.json` | フォーム・ビュー・サイトマップの定義（人が読む・編集するのはここ） |
| `Build-Solution.ps1` | zip を組み立てる（通信しない） |
| `Test-SolutionPackage.ps1` | 出来上がった zip を取り込む前に検査する（通信しない） |
| `dist/` | 生成物 |

## 前提：先にテーブルを作っておく

このソリューションは**既存のテーブルに重ねる**形です。テーブル自体は含まれていません。

```powershell
cd ..\scripts
.\Deploy-Schema.ps1   -EnvironmentUrl 'https://<組織名>.crm7.dynamics.com'
.\Deploy-Security.ps1 -EnvironmentUrl 'https://<組織名>.crm7.dynamics.com'
```

テーブルがない状態で取り込むと、依存関係のエラーになります。

## 取り込みかた

1. `dist\EquipmentManagementApp_1_0_0_0.zip` を用意する（このリポジトリに入っています）
2. make.powerapps.com > **ソリューション** > **ソリューションのインポート**
3. zip を選んで取り込む（アンマネージドです）
4. 取り込み後、**すべてのカスタマイズを公開**する
5. アプリ「設備管理（管理者）」を「設備-管理者」チームに共有する

## zip は2つあります。どちらか一方だけを取り込みます

| ファイル | 中身 | 使いどころ |
|---|---|---|
| `EquipmentManagementApp_1_0_0_0.zip` | フォーム＋ビュー＋サイトマップ＋アプリ | 通常はこちら |
| `EquipmentManagementApp_1_0_0_0_formsviews.zip` | フォーム＋ビューのみ | 上がアプリの部分でエラーになったとき |

**アプリの取り込みでエラーになった場合**は `_formsviews` のほうを取り込んでください。
フォームとビュー（作業量のほとんど）は入った状態になるので、
あとはメーカーポータルで「新規アプリ > モデル駆動」を作り、サイトマップに
8つのテーブルを並べるだけです（数分で終わります）。

## 入っているもの

**フォーム 8 件**（テーブルごとに1つ）

設備は3タブ構成です。

| タブ | 内容 |
|---|---|
| 基本情報 | 設備コード・短縮番号・設備名・種別・場所・管理部署・型式・製造番号・導入日・貸出可否・備考 |
| 状態 | ステータス／現在の使用者／現在の稼働ログ／現在の使用開始日時（**すべて読み取り専用**）、ラベル貼付状況、稼働ログのサブグリッド |
| メンテナンス | メンテ周期日数・前回／次回メンテ日・稼働可能時間、貸出のサブグリッド |

**ビュー 26 件**

| テーブル | ビュー |
|---|---|
| 設備 | アクティブな設備 / 使用中の設備 / **長時間稼働中の設備** / **ラベル未貼付一覧** / メンテ期限切れの設備 / メンテ期限が近い設備 / メンテ期限が未設定の設備 / 故障・メンテ中の設備 |
| 稼働ログ | アクティブな稼働ログ / 本日のログ / 稼働中のログ / 強制終了されたログ / 今月のログ / 設備別の稼働ログ |
| 貸出 | アクティブな貸出 / 貸出中 / **延滞** / 今週返却予定 / 返却済（今月） / 設備別の貸出 |
| 使用者 | 有効な使用者 / **UPN 未設定の使用者** |
| マスタ4種 | 有効な〜 各1件 |

**サイトマップ**：日常（設備・稼働ログ・貸出）／マスタ（使用者・設備種別・場所・部署・貸出先）

## 入っていないもの（手作業が残ります）

| 項目 | 理由 | 手順 |
|---|---|---|
| カスタムコマンド（4-8〜4-10） | Power Fx コマンドはソリューション XML で表現しにくい | [docs/phase4-admin-app.md](../docs/phase4-admin-app.md) に数式あり |
| ダッシュボード（4-7） | グラフ定義まで作ると壊れやすい | 同上 |
| 使用者アプリ（キャンバス） | `.msapp` は内部形式で、手で作ると壊れる | [powerfx/](../powerfx/) の数式を貼り付ける |
| ビジネスルール（1-10） | Web API でもソリューション XML でも作れない | [docs/phase1-data.md](../docs/phase1-data.md) |

## 作り直すとき

`app-definition.json` を直してから、

```powershell
.\Build-Solution.ps1
.\Test-SolutionPackage.ps1
```

**GUID は名前から決まる値（UUID version 5）です。** 作り直しても同じ ID になるので、
再インポートは追加ではなく更新になります。ビューの名前を変えると別 ID になり、
古いビューが残る点にだけ注意してください。

3回ビルドして中身が1バイトも変わらないことを確認してあります。

### スキーマを変えたら

```powershell
..\scripts\Test-Solution.ps1
```

列の表示名や論理名を変えると、アプリ定義のビュー・フォームがずれます。
このチェックがそれを見つけます。**先にこれを流してから** `Build-Solution.ps1` を実行してください。

## 取り込み後に確認すること

- [ ] アプリ一覧に「設備管理（管理者）」が出ている
- [ ] 設備を開くと3タブ構成になっていて、状態タブが編集できない
- [ ] 「ラベル未貼付一覧」が場所順に並ぶ
- [ ] 設備フォームの状態タブに稼働ログのサブグリッドが出る
- [ ] アプリを「設備-管理者」チームに共有した

### テーブルごとにフォームが2つ表示される場合

テーブルを作った時点で Dataverse が既定のフォーム（主キー列だけのもの）を自動生成します。
このソリューションのフォームはそれとは別に追加されるため、フォーム選択に2つ並ぶことがあります。

気になる場合は、**設定 > フォーム** で自動生成されたほうを「非アクティブ化」するか、
アプリのフォーム構成からこのソリューションのフォームだけを選んでください。

## 確認できていないこと

**実環境への取り込みは確認していません。** XML の構成・参照の整合・GUID の妥当性は
`Test-SolutionPackage.ps1` で検査していますが、Dataverse が受け付けるかどうかは
実際に取り込むまで分かりません。

**必ず開発環境で先に試してください。** アンマネージドなので、取り込み後に
メーカーポータルで自由に直せます。取り込みに失敗した場合は何も入りません。
