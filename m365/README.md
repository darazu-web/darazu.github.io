# 検査情報アプリ（Microsoft 365 版）

製品の検査時に「検査項目・検査方法・使用設備・特記事項」を確認するアプリです。
**SharePoint リスト**にデータを保存し、**Power Apps** で画面を作ります。
社内の Microsoft 365 アカウントでサインインした人だけが使え、社外には公開されません。

```
 作業者（閲覧のみ） ─┐                      ┌─ InspProducts   製品
                      ├─ Power Apps ─────────┼─ InspItems      検査項目
 管理者（編集可）   ─┘  （PC・タブレット・  └─ InspEquipment  使用設備
                          スマホ・Teams）        （SharePoint リスト）
```

## 管理者だけが変更できる仕組み

| | 作業者 | 管理者 |
| --- | --- | --- |
| SharePoint リストの権限 | **閲覧** | 編集（またはフル コントロール） |
| アプリの「管理」ボタン | 表示されない | 表示される |

アプリは、ログインした人がリストを編集できるかどうか（`DataSourceInfo(InspItems, DataSourceInfo.EditPermission)`）を確認し、編集できる人にだけ「管理」ボタンを表示します。
変更を実際に止めているのは SharePoint の権限です。作業者がリストを直接開いても閲覧しかできません。
SharePoint のバージョン履歴が有効なので、誰がいつ何を変更したかを確認し、元に戻すこともできます。

## 必要なもの

- Microsoft 365 のビジネス向けライセンス（Power Apps を SharePoint と組み合わせて使う範囲は、通常の Microsoft 365 ライセンスに含まれます）
- アプリ用の SharePoint サイト（新しく作るのがおすすめ）
- 手順 2 をスクリプトで行う場合：PowerShell 7 と PnP.PowerShell

## ファイル

| ファイル | 内容 |
| --- | --- |
| `Setup-InspectionLists.ps1` | SharePoint リストを作成し、サンプルデータを登録するスクリプト |
| `sample-data.json` | 取り込み用データ（記入例。Web 版の `data.json` と同じ形式） |
| `powerapps/App.OnStart.txt` | アプリの OnStart に貼り付ける数式 |
| `powerapps/scrBrowse.pa.yaml` | 閲覧画面（画面に貼り付ける） |
| `powerapps/scrAdmin.pa.yaml` | 管理画面（画面に貼り付ける） |
| `tools/build_powerapps.py` | 上の 3 ファイルを生成するスクリプト（画面を変更するときに使う） |
| `tools/fxcheck/` | 数式の文法・型チェック用ツール（.NET 8） |

## セットアップ手順

### 1. SharePoint サイトを用意して権限を設定する

1. SharePoint で「サイトの作成」→「チーム サイト」（または「コミュニケーション サイト」）を作成します。例：`検査情報`
2. 歯車アイコン →「サイトのアクセス許可」で、次のように設定します。
   - **管理者** → 所有者（またはメンバー）
   - **検査作業者** → **閲覧者**（ビジター）

> 作業者がすでにメンバーに入っている既存のサイトを使う場合は、手順 2 のスクリプトに `-MembersReadOnly` を付けて実行してください。3 つのリストだけ権限の継承を切り、メンバーを閲覧のみにします（編集できるのは所有者だけになります）。

### 2. SharePoint リストを作成する

#### 方法 A：スクリプトで作成する（おすすめ）

1. PowerShell 7 で PnP.PowerShell をインストールします。
   ```powershell
   Install-Module PnP.PowerShell -Scope CurrentUser
   ```
2. PnP PowerShell 用の Entra ID アプリを登録します（テナントで 1 回だけ。管理者の同意が必要な場合は IT 管理者に依頼してください）。
   ```powershell
   Register-PnPEntraIDAppForInteractiveLogin -ApplicationName "PnP Inspection Setup" -Tenant contoso.onmicrosoft.com
   ```
   表示された **ClientId** を控えておきます。
3. スクリプトを実行します。
   ```powershell
   ./Setup-InspectionLists.ps1 -SiteUrl https://contoso.sharepoint.com/sites/Inspection -ClientId <ClientId>
   ```
   - データを入れずにリストだけ作る場合：`-SkipData`
   - 既存サイトでメンバーを閲覧のみにする場合：`-MembersReadOnly`
   - 別のデータを取り込む場合：`-DataJson <ファイルのパス>`（Web 版の `inspection/data.json` もそのまま使えます）

スクリプトは何度実行しても大丈夫です。既にあるリスト・列・同じ品番の製品はスキップします。

#### 方法 B：ブラウザーで手作業で作成する

サイトの「＋新規」→「リスト」→「空白のリスト」で、次の 3 つのリストを作ります。
**リスト名と列名は下の表のとおり半角英字で入力してください**（アプリの数式がこの名前を使います）。
「タイトル」列（Title）は最初からあるので、名前を変えずにそのまま使います。

**InspProducts**（製品）

| 列名 | 種類 | 内容 |
| --- | --- | --- |
| Title（既存） | 1 行テキスト | 製品品番（リストの設定で「一意の値を適用する」をオン） |
| ProductName | 1 行テキスト | 製品名 |
| Description | 複数行テキスト | 説明・備考 |

**InspItems**（検査項目）

| 列名 | 種類 | 内容 |
| --- | --- | --- |
| Title（既存） | 1 行テキスト | 検査項目名 |
| ProductID | 数値 | 製品の ID（InspProducts の ID） |
| ItemNo | 数値 | 検査項目 No.（並び順） |
| Category | 1 行テキスト | 分類 |
| Method | 複数行テキスト | 検査方法（1 行が 1 ステップ） |
| Criteria | 複数行テキスト | 判定基準 |
| TesterNo | 1 行テキスト | テスター品番 |
| TesterName | 1 行テキスト | テスター名 |
| Notes | 複数行テキスト | 特記事項 |
| Other | 複数行テキスト | その他 |

**InspEquipment**（使用設備）

| 列名 | 種類 | 内容 |
| --- | --- | --- |
| Title（既存） | 1 行テキスト | 名称 |
| ItemID | 数値 | 検査項目の ID（InspItems の ID） |
| ProductID | 数値 | 製品の ID |
| EquipType | 1 行テキスト | `周辺設備` / `ハーネス` / `ソフトウェア` |
| Code | 1 行テキスト | 品番（ソフトウェアはバージョン） |
| Note | 1 行テキスト | 備考 |
| SeqNo | 数値 | 表示順 |

- 複数行テキストの列は「拡張リッチテキスト」を**オフ**（書式なしテキスト）にしてください。
- 「リストの設定」→「インデックス付きの列」で `ProductID`（両リスト）と `ItemID` にインデックスを付けておくと、データが増えても速く動きます。
- データの登録は、手順 3 のアプリの管理画面から行えます。

### 3. Power Apps でアプリを作る

1. [Power Apps](https://make.powerapps.com) を開き、環境が自社の既定の環境になっていることを確認します。
2. 「作成」→「空のキャンバス アプリ」→ 形式は **タブレット** を選び、名前を `検査情報` にして作成します。
3. **データを追加**：左の「データ」→「データの追加」→「SharePoint」→ 手順 1 のサイトを選び、
   `InspProducts`・`InspItems`・`InspEquipment` の 3 つにチェックを入れて接続します。
4. **設定**：「設定」→「全般」→「データ行の制限」を **2000** にします。
5. **画面を用意**：ツリー ビューの `Screen1` の名前を `scrBrowse` に変えます。
   「＋ 新しい画面」→「空」で画面を追加し、名前を `scrAdmin` にします。
6. **OnStart を貼り付け**：ツリー ビューで `App` を選び、プロパティ `OnStart` に
   `powerapps/App.OnStart.txt` の内容をすべて貼り付けます。
7. **画面を貼り付け**：
   - `powerapps/scrBrowse.pa.yaml` の内容をすべてコピー → ツリー ビューで `scrBrowse` を右クリック →「貼り付け」（または `scrBrowse` を選択して Ctrl+V）
   - 同じように `powerapps/scrAdmin.pa.yaml` を `scrAdmin` に貼り付け
8. ツリー ビューで `App` の「…」→「**OnStart を実行**」を選び、データを読み込みます。
9. 「保存」→「公開」します。
10. **共有**：「共有」から作業者・管理者のユーザー（またはグループ）を追加します。
    ここで追加した人がアプリを開けます。編集できるかどうかは手順 1 の SharePoint の権限で決まります。

#### 使う場所

- PC：ブラウザーでアプリの URL を開く
- タブレット・スマホ：**Power Apps モバイル アプリ**（iOS / Android）
- Teams：チャネルの「＋（タブを追加）」→「Power Apps」→ このアプリを選ぶ

## アプリの使い方

### 閲覧画面（全員）

- 上部で製品を選ぶと、左に検査項目の一覧が表示されます。
- 項目を選ぶと右側に、**特記事項**（黄色の警告枠）、**検査方法**（番号付きの手順）、判定基準、
  **使用設備**（テスター品番・テスター名・周辺設備・ハーネス・ソフトウェア）、その他が表示されます。
- 下の「次の項目 →」ボタンで検査の順番どおりに進めます。
- 検索欄で、項目名・品番・設備名・ハーネス品番などから絞り込めます。
- 「設備まとめ」で、その製品の検査に必要な設備と、それを使う検査項目 No. を一覧で確認できます（検査前の準備用）。

### 管理画面（管理者のみ）

- 「管理」ボタンで開きます（編集権限のある人にだけ表示されます）。
- **製品**：「＋ 製品」で追加し、品番・製品名・説明を入力して「製品情報を保存」。
  「製品を削除」は 2 回押すと削除されます（その製品の検査項目・設備もすべて削除されます）。
- **検査項目**：「＋ 検査項目」で追加、一覧から選んで編集し「保存」。
  - 検査方法は 1 行が 1 ステップになります。
  - 使用設備は「＋ 設備を追加」で行を増やし、種類（周辺設備／ハーネス／ソフトウェア）を選びます。
  - No. を変えると並び順が変わります。
- 「閲覧画面へ戻る」で最新の内容を読み込み直して閲覧画面に戻ります。

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| 貼り付けでエラーになる | Studio が古い／新しいコントロールのバージョンを求めている可能性があります。エラーに出たコントロールだけ手動で追加し、`.pa.yaml` に書かれている各プロパティの数式（`=` 以降）をコピーしてください。 |
| 数式に赤い波線が出る | データ ソース名・列名が手順 2 の表と一致しているか確認してください（大文字・小文字も含む）。 |
| 青い波線（委任の警告）が出る | 検索などデータ件数が少ないうちは問題ありません。手順 3-4 の「データ行の制限」を 2000 にしておけば、検査項目 2000 件まで正しく動きます。 |
| 一覧が空のまま | `App` の「OnStart を実行」を行ってください。公開後のアプリは起動時に自動で実行されます。 |
| 「管理」ボタンが出ない | そのユーザーに SharePoint リストの編集権限がありません（意図どおりの動作です）。 |

## 画面を変更するとき

`powerapps/` のファイルは `tools/build_powerapps.py` から生成しています。
スクリプトを変更して次を実行すると、ファイルが再生成され、数式のチェックが行われます（.NET 8 SDK が必要です）。

```bash
python3 m365/tools/build_powerapps.py
cd m365/tools/fxcheck && python3 export_formulas.py && dotnet run -- formulas.json
```

Studio で直接変更した場合は、ツリー ビューで画面を右クリック →「コードの表示」でコピーし、ファイルを更新しておくと管理しやすくなります。
